# 角色生成器项目工作日志

## 项目概述
角色生成器是一个基于Vue 3和ComfyUI API的图像生成应用，支持批量生成、TXT转JSON等功能。

## 已实现功能

### 1. 核心功能
- **批量图片生成**：支持从JSON文件中读取多个分镜提示词，批量生成图片
- **TXT转JSON**：将分镜TXT文件转换为JSON格式，方便批量生成
- **工作流上传**：支持上传自定义ComfyUI工作流文件
- **配置持久化**：使用localStorage保存配置，刷新页面后不会丢失
- **图片存放目录配置**：支持指定自定义的图片存放目录

### 2. 界面优化
- **选项卡布局**：将功能分为配置选项、生成选项、批量生成和TXT转JSON四个选项卡
- **简化生成结果**：只显示生成状态和数量，不显示图片和下载按钮
- **响应式设计**：支持深色模式和浅色模式

## 技术实现

### 1. 主要文件
- `src/App.vue`：主应用组件，包含所有功能和界面
- `parse_storyboard.js`：TXT转JSON的解析脚本

### 2. 关键功能实现

#### 批量生成
- 读取JSON文件中的分镜提示词
- 循环处理每个提示词，调用ComfyUI API生成图片
- 显示生成进度和状态

#### TXT转JSON
- 解析TXT文件中的分镜结构
- 提取分镜的视角、角色动作与构图、灯光气氛、场景环境等信息
- 生成包含id和prompt字段的JSON文件

#### 工作流上传
- 读取上传的JSON工作流文件
- 自动修复工作流中的兼容性问题（如CLIPLoaderGGUF节点类型）
- 保存工作流到localStorage

#### 配置持久化
- 使用localStorage保存配置选项
- 组件挂载时自动加载保存的配置

#### 图片存放目录配置
- 在配置选项中添加图片存放目录输入框
- 在API请求中传递output_dir参数
- 处理路径中的反斜杠，确保路径格式正确

### 3. API调用
- 使用fetch API调用ComfyUI的`/api/prompt`端点
- 传递工作流和output_dir参数
- 轮询`/api/history`端点获取生成状态

## 问题与解决方案

### 1. GGUF文件架构类型错误
- 问题：`Unexpected architecture type in GGUF file, expected one of flux, sdl, sdxl, t5encoder but got 'qwen3'`
- 解决方案：修改工作流，将CLIPLoaderGGUF节点的type改为stable_diffusion，或切换到CLIPLoader节点

### 2. 配置不持久化
- 问题：配置在页面刷新后丢失
- 解决方案：使用localStorage保存配置，组件挂载时加载

### 3. 工作流兼容性问题
- 问题：`Value not in list: type: 'qwen_image' not in ['stable_diffusion', 'stable_cascade', 'sd3', 'stable_audio', 'mochi', 'ltxv', 'pixart']`
- 解决方案：实现自动工作流兼容性修复，检测并修正节点类型

### 4. 图片存放目录不生效
- 问题：指定的图片存放目录不生效，图片仍保存到默认目录
- 解决方案：在API请求中传递output_dir参数，并确保路径格式正确

### 主要问题：图片无法显示

#### 问题现象
1. ComfyUI生成图片成功后，页面显示"生成完成"，但图片无法显示
2. 尝试通过WebSocket接收ComfyUI的二进制图片数据，但ComfyUI不会主动发送二进制数据
3. 图片URL使用直接路径（如`/view/...`或`http://127.0.0.1:8188/view/...`），存在跨域问题

#### 解决方案探索过程

**方案1：WebSocket二进制数据传输**
- 尝试通过WebSocket连接接收ComfyUI发送的图片数据
- 发现ComfyUI的WebSocket只会发送状态消息（JSON），不会主动发送二进制图片数据
- 此方案失败

**方案2：Vite代理配置**
- 尝试配置Vite代理，将`/view`路径代理到ComfyUI
- 配置了`/view`代理，但仍然无法正确转发请求
- 原因：Vite开发服务器的代理配置存在限制，`ERR_INVALID_RESPONSE`错误

**方案3：图片URL格式调整**
- 参考ComfyUI示例项目，发现正确的URL格式是：`/api/view?filename=xxx&subfolder=xxx&type=output`
- 而不是直接使用`/view/xxx`
- 同时需要正确配置Vite代理，将`/api`路径代理到ComfyUI，并移除`/api`前缀

**方案4：动态API地址选择**
- 发现用户的ComfyUI可能是远程服务器（如`https://201viuoslp-8188.cnb.run/`）
- 原代码硬编码了`http://127.0.0.1:8188`，无法灵活切换
- 添加了`isLocalComfyUI()`和`getApiBaseUrl()`函数
- 本地地址（127.0.0.1/localhost）使用代理
- 远程地址直接使用完整URL

### 最终解决方案

1. **图片URL格式**：使用`/api/view?filename=xxx&subfolder=xxx&type=output`格式
2. **Vite代理配置**：
   ```javascript
   '/api': {
     target: 'http://127.0.0.1:8188',
     changeOrigin: true,
     rewrite: (path) => path.replace(/^\/api/, ''),
     configure: (proxy) => {
       proxy.on('proxyReq', (proxyReq) => {
         proxyReq.setHeader('Host', '127.0.0.1:8188');
         proxyReq.setHeader('Origin', 'http://127.0.0.1:8188');
       });
     }
   }
   ```
3. **动态地址选择**：根据配置的ComfyUI地址自动选择使用代理还是直接访问

### 主要问题：自定义工作流兼容性问题

#### 问题现象
1. 更换为远程ComfyUI地址（`https://a0cikoj26f-8188.cnb.run/`）后出现错误
2. 错误1：`Node '全局样式' has no class_type. The workflow may be corrupted or a custom node is missing.`
3. 错误2：`Cannot read properties of undefined (reading 'inputs')`

#### 问题原因
1. 自定义工作流可能包含无效节点（缺少class_type）
2. 自定义工作流不一定包含默认工作流中的特定节点（如节点109、节点84）
3. 代码直接访问特定节点的inputs属性，当节点不存在时会崩溃

#### 解决方案

**1. 添加工作流验证函数**
- 实现 `validateWorkflow()` 函数，检查所有节点是否都有 class_type
- 如果验证失败，自动回退到默认工作流
- 在控制台输出警告信息，提示哪个节点有问题

**2. 完善 updateWorkflow 函数的安全检查**
- 添加 `promptSet` 标志位跟踪提示词是否成功设置
- 检查节点109时，不仅检查节点和inputs是否存在，还检查是否有 'text' 属性
- 扩展搜索范围：查找其他节点时，不再限制必须是 'Text Multiline' 类型，任何有 'text' 输入的节点都可以使用
- 如果实在找不到合适的节点，自动创建一个新的文本输入节点来存放提示词
- 对所有节点访问都添加了存在性检查（包括批量大小节点和保存节点）

**3. 增强日志输出**
- 添加详细的console.log，方便调试
- 记录使用了哪个节点作为提示词输入
- 当无法找到节点时输出警告信息

1. **防御性编程**：在访问对象属性前先检查对象是否存在
